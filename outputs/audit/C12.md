### L25564 | 第15章1题 | 线程数推导公式
- 类型：1
- 严重度：P0
- 原文：「不按 CPU 核数 ×2 计算（那是 CPU 密集型的算法）」
- 问题：公式说反了。业界经验公式是 **CPU 密集型 = 核数+1**，**IO 密集型 = 核数×2（更准确是 核数 × 目标利用率 × (1+等待/计算)）**。把「核数×2」归给 CPU 密集型是硬错误，L26495 又原样重复了一遍。
- 建议：改成「CPU 密集型取 核数+1；IO 密集型取 核数×(1+W/C) 或核数×2 起步；本例进一步用下游配额反推」。两处同时改。

### L26395 | 第15章21题 | javax→jakarta 的归因
- 类型：2
- 严重度：P0
- 原文：「**废弃 API**：`javax` 部分包迁移到 `jakarta`（JDK11+）」
- 问题：事实错误。`javax.*` → `jakarta.*` 是 **Jakarta EE 9 改名（2020）+ Spring Boot 3.0** 带来的，**与 JDK 版本无关**；JDK 11 干的是 JEP 320 移除 Java EE/CORBA 模块（JAXB、JAX-WS、JAF 等从 JDK 里剥离），所以迁移时是"加第三方 `javax.xml.bind:jaxb-api` 依赖"，不是"改名成 jakarta"。两条因果被搅在一起。

### L26433 / L26448 / L26450 | 第15章22题 | Redisson 看门狗与 leaseTime 冲突
