### L1801 | 第二章第2题 | Spring AI 2.0 实现
- 类型：2
- 严重度：P1
- 原文：「所以自己写 ReAct 循环时仍要手动执行工具再回灌」
- 问题：与本文 L11805–L11820（第55题）冲突：那里明确 2.0 由 ChatClient 自动注册的 ToolCallingAdvisor 负责完整「模型→工具→模型」往返，手写执行会重复执行工具（副作用工具执行两遍）。按注释前提，本段手写 execute() 要么永不被触发（advisor 已返回最终答案），要么副作用重复，与自述相反。
- 建议：2.0 段删掉手写循环，一行依赖 advisor；若保留手写循环，须说明关闭自动注册（AdvisorParams.toolCallingAdvisorAutoRegister(false)）或改走 ChatModel + ToolCallingManager。

### L2354 | 第二章第16题 | 短期记忆实现
- 类型：2
- 严重度：P0
- 原文：「String chat(@V("conversationId") String conversationId, ...)」
- 问题：`@V` 只把参数当模板变量，AiServices 不会据此选 ChatMemory；chatMemoryProvider 的 id 拿不到值，所有会话共用同一份记忆（串号）。LangChain4j 必须用 `@MemoryId`，本文 L8930、L18236、L20076 等处正是这么写的，前后不一致。
- 建议：改为 `@dev.langchain4j.service.MemoryId String conversationId`，并从 `@UserMessage` 模板中移除该变量。

### L2648 | 第二章第21题 | Reflection 实现
- 类型：5
- 严重度：P1
- 原文：「// 关键：审查时不要给模型看初答，避免它顺着原答案附和」
- 问题：紧接着的代码 `.param("a", draft)` 就是把初答作为「待审内容」传给审稿模型；类头注释「别参考初答」同样与实现相反。不传初答也无从审稿。
