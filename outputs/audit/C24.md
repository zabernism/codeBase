### L56519 | 第34章35题 | TCC 报告生成+配额扣减
- 类型：1（事实错误）/5（逻辑矛盾）
- 严重度：P1 过时不准
- 原文：「Confirm 用实际消耗更新余额（`balance -= actual; frozen -= actual`）」
- 问题：Try 冻结的是上限 N（frozen += N），Confirm 时必须把整个 N 释放，只减 actual 会永久残留 `N - actual` 的冻结量，配额泄漏且随时间累积，正好违背本题要防的"配额被永久钉死"。正确应为 `balance -= actual; frozen -= N`。
- 建议：写成「Try：`frozen += N`；Confirm：`balance -= actual; frozen -= N`（余量 N-actual 自动回补）；Cancel：`frozen -= N`」，并说明 N 即冻结上限。

### L56435 | 第34章31题 | 幂等标记排除重试
- 类型：5（逻辑矛盾）
- 严重度：P1 过时不准
- 原文：「消息消费侧对可安全重试的幂等操作标记 `idempotent=false`（即该步骤非天然幂等，须显式去重）」

### L56700 | 第35章8题 | 碳核算全生命周期审计日志

### L56736 | 第35章10题 | 绿电/绿证抵扣履约

### L56949 | 第36章4题 | 快慢指针判环
- 类型：1（事实错误）
- 严重度：P2 质量偏低
- 原文：「走 3 步在环长与步长不互质时可能跳过」
- 问题：判据写错了。快指针走 3、慢走 1，相对速度是 2，能否相遇取决于 `gcd(2, 环长 L)` 是否为 1，与"步长 3 和环长是否互质"无关。反例：L=9，gcd(3,9)=3（不互质）但 gcd(2,9)=1，实际一定会相遇；L=6 时 gcd(2,6)=2，才真的永远追不上。照原文说法在 L=9 时会得出错误结论。
- 建议：改为「能否相遇取决于相对速度 (k-1) 与环长 L 是否互质：走 2 步时相对速度 1 恒互质，必然相遇；走 3 步时相对速度 2，环长为偶数就永远追不上，故实现上取 2 步」。

### L57046 | 第36章9题 | 二叉树遍历
- 类型：1（事实错误）
- 严重度：P2 质量偏低
- 原文：「访问到第 k 个立即抛自定义异常或设 flag 终止……O(k) 而非 O(n)」
- 问题：复杂度不成立。中序访问到第 k 个节点必须先把左侧链压栈，最坏（退化成链表）栈深已是 O(n)，时间也是 O(n)；只有平衡树才近似 O(k + log n)。原答案把"剪枝"直接等同于 O(k)。
- 建议：改为「剪枝后为 O(h + k)（h 为树高），最坏仍 O(n)；要真 O(k) 需带子树 size 的增强树（order-statistic tree）做定位」。

### L57093 | 第36章12题 | 堆求 TopK 高频元素
- 类型：1（事实错误）
- 严重度：P1 过时不准
- 原文：「Java：`PriorityQueue<Map.Entry<Integer,Integer>> pq=(a,b)->a.getValue()-b.getValue();`」
- 问题：这行代码编译不过。Lambda 不能直接赋给 `PriorityQueue` 类型（`PriorityQueue` 不是函数式接口），必须 `new PriorityQueue<>((a,b)->...)`。且 `getValue()-getValue()` 是 Integer 拆箱相减，频次差超过 int 范围会溢出——恰好是本题下一行"易错点"自己点出的问题，示例代码却踩了。
- 建议：改为 `PriorityQueue<Map.Entry<Integer,Integer>> pq = new PriorityQueue<>(Map.Entry.comparingByValue());`（升序=小顶堆），并在正文说明"要降序则 `Comparator.comparingInt(Map.Entry<Integer,Integer>::getValue).reversed()`"。
