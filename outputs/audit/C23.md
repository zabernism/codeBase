# C23 审校：第三十章 通用安全（17题）+ 第三十一~三十三章 碳领域（58题）

## 第三十章 通用安全：认证授权与 Spring Security（Q1-Q17）

### L54520 | 第三十章13题 | Spring Security 过滤器链顺序
- 类型：2 API/版本错误
- 严重度：P0
- 原文：「SecurityContextPersistenceFilter（载入上下文）→ AuthenticationFilter → ExceptionTranslationFilter → AuthorizationFilter → CsrfFilter、CorsFilter」
- 问题：①顺序错：`CorsFilter`、`CsrfFilter` 在认证过滤器**之前**（CorsFilter 紧跟 HeaderWriterFilter，CsrfFilter 在 LogoutFilter 之前），文中把它们排在 AuthorizationFilter 之后；②`SecurityContextPersistenceFilter` 在 5.7 起弃用、6.x 默认链已换成 `SecurityContextHolderFilter`（7.0 移除），写成 6.x 核心组件属版本错误；③漏掉 `HeaderWriterFilter`/`LogoutFilter` 等锚点，追问里用 `UsernamePasswordAuthenticationFilter.class` 作锚点尚可，但主链顺序已错。
- 建议：改为「HeaderWriterFilter → CorsFilter → CsrfFilter → LogoutFilter → UsernamePasswordAuthenticationFilter → … → ExceptionTranslationFilter → AuthorizationFilter」，并注明 `SecurityContextHolderFilter` 替代关系与 6.0 移除 `WebSecurityConfigurerAdapter`、改为 `SecurityFilterChain` Bean 的写法。

### L54309 | 第三十章2题 | Cookie 与 JWT 跨域
- 类型：1 事实错误
- 严重度：P1
- 原文：「JWT 通常放 Authorization 头，天然跨域且不被 CORS 预检限制」
- 问题：`Authorization` 属非简单请求头，**一定触发 CORS 预检**（OPTIONS + Access-Control-Request-Headers）。真正"不被预检限制"的是简单请求（GET/HEAD/POST + 三类简单头）。此说法会让人误以为加了 Authorization 头就免预检。
- 建议：改为「JWT 放 Authorization 头，跨域时仍需服务端配置 CORS 白名单并放行该头（触发预检）；相比 Cookie 的优势是不依赖 `withCredentials`、不受 SameSite 限制，代价是 JS 可读、有 XSS 泄露风险，故也可用 HttpOnly Cookie 承载」。

### L54343 | 第三十章4题 | OAuth2 四种授权模式
- 类型：2 API/版本错误（规范已变）
- 严重度：P1
- 原文：「RFC 6749 定义四种模式，RFC 9700 已明确弃用隐式与密码模式」
- 问题：题干仍按"四种模式"设问，未体现 **OAuth 2.1**（draft-ietf-oauth-v2-1）已把授权类型收敛为「授权码 + 客户端凭证」两种、删除 Implicit 与 ROPC、并对**所有**客户端（含机密客户端）强制 PKCE；参考答案①授权码模式也未写 PKCE。RFC 9700 是 Security BCP（2025-01 发布），措辞是 "MUST NOT use implicit / resource owner password"，比"弃用"更强。
- 建议：题干加一问「OAuth 2.1 相对 2.0 的关键变更」；答案补：删 Implicit/ROPC、PKCE 强制（S256）、redirect_uri 精确匹配、禁止 bearer token 走 URI query、refresh token 对公共客户端必须轮换或 sender-constrained。

### L54284 | 第三十章1题 | 未认证时的异常类型
- 类型：1 事实错误
- 严重度：P2
- 原文：「AuthorizationFilter 在 Authentication 缺失时会抛出 AuthenticationCredentialsNotFoundException」
- 问题：`AuthenticationCredentialsNotFoundException` 是旧 `AbstractSecurityInterceptor`（FilterSecurityInterceptor）链路的异常；6.x 的 `AuthorizationFilter` 在鉴权不通过时抛 `AccessDeniedException`，再由 `ExceptionTranslationFilter` 判定「匿名/未认证 → 401、已认证 → 403」。表述与 13 题自相矛盾。
- 建议：改为「AuthorizationFilter 抛 AccessDeniedException，ExceptionTranslationFilter 依据 Authentication 是否为匿名决定 401 还是 403；AuthenticationCredentialsNotFoundException 属旧 FilterSecurityInterceptor 时代的说法」。

## 第三十一章 碳足迹核算（Q1-Q18）

### L54646 | 第三十一章2题 | Scope 2 地点基因子来源
- 类型：1 事实错误
- 严重度：P1
- 原文：「地点基因子用区域/国家电网平均因子（如生态环境部发布的区域电网基准线排放因子）」
- 问题：**基准线排放因子 ≠ 消费侧电网平均因子**。生态环境部每年发布的「区域电网基准线排放因子」含 OM（电量边际）/BM（容量边际），是 CDM/CCER 项目减排量计算用的基准线口径；企业 Scope 2 地点基用的是「全国电力平均二氧化碳排放因子 / 区域电网平均排放因子」（2024 年起生态环境部与统计局联合发布，2022 年全国电力平均约 0.5366 kgCO₂/kWh）。两套数值与用途都不同，混用会导致 Scope 2 直接算错。同一错误在 5 题追问 1（L54719「分电量边际与容量边际」）重复出现。
- 建议：改为「地点基采用生态环境部/国家统计局发布的全国及区域电网**平均**二氧化碳排放因子（含/不含市场化交易电量两种口径）；OM/BM 基准线因子仅用于减排项目基准线，不可用于企业碳核算」，并在 5 题追问里同步改口径。

### L54670 | 第三十一章3题 | 国内政策文件引用
- 类型：3 数字/文号错误
- 严重度：P1
- 原文：「《关于建立统一规范的碳排放统计核算体系实施方案》（国办函〔2022〕123号）」
- 问题：三处不准：①正式名称是《关于**加快**建立统一规范的碳排放统计核算体系实施方案》；②发文号是 **发改环资〔2022〕622号**（2022-04-22，国家发改委、国家统计局、生态环境部三部门联合印发），不是国办函；③发布主体不是国务院办公厅。
- 建议：改为「《关于加快建立统一规范的碳排放统计核算体系实施方案》（发改环资〔2022〕622号，发改委/统计局/生态环境部）」；若要引国办文件，可另引《加快构建碳排放双控制度体系工作方案》（国办发〔2024〕27号）。

### L54690 | 第三十一章4题 | GWP 版本与数值
- 类型：3 数字错误 / 2 版本错误
- 严重度：P1
- 原文：「IPCC《国家温室气体清单指南》2006 及 2019 修订版…（AR5 中 CH₄=28、N₂O=265）」
- 问题：①2006 年原版指南用的是 **AR4** 值（CH₄=25、N₂O=298），AR5 值（28/265）是 2019 修订版才引入的可选更新，笼统说"2006 及 2019 修订版给出 AR5 值"不准确；②未给 AR6 数值（**CH₄=27.9（化石源 29.8、非化石源 27.0）、N₂O=273**），而 IFRS S2 及 2025-12 修订明确要求用「报告日可得的最新 IPCC 评估报告」的 GWP100，即 AR6；③国内《省级温室气体清单编制指南》仍用 SAR 值（21/310），发电行业核算指南用 AR4/AR5 口径——这个"三套口径并存"恰恰是最容易追问的点，文中未提。
- 建议：列一张小表：SAR(21/310) / AR4(25/298) / AR5(28/265) / AR6(27.9 或 29.8 / 273)，并注明"中国官方核算指南按指南指定版本、ISSB 按最新 AR、跨年比较须锁定版本"。

### L54688 | 第三十一章4题 | 燃煤示例数值
- 类型：3 数字错误
- 严重度：P2
- 原文：「燃煤 100 吨、因子 2.66 tCO₂e/t，则排放 266 tCO₂e」
- 问题：2.66 tCO₂/t 是**标准煤（tce）**量级的因子（约 2.6–2.8 tCO₂/tce），原煤实测约 **1.9 tCO₂/t**（烟煤约 1.90、无烟煤约 2.77）。用 2.66 当"燃煤"因子会让示例虚高约 40%，面试官一问"你用的是原煤还是标煤"就露馅。
- 建议：改为「原煤 100 t × 1.9003 tCO₂/t ≈ 190 tCO₂；若活动数据是标准煤，则 100 tce × 2.66 ≈ 266 tCO₂」，并强调"活动数据与因子必须同一物料口径（原煤/标煤/熟料）"。

### L54628 | 第三十一章1题 | Scope 2 边界表述
- 类型：5 逻辑矛盾
- 严重度：P2
- 原文：「Scope 2 仅含外购电力热力」
- 问题：与本题参考答案「外购电力、蒸汽、热力或冷力」自相矛盾，漏掉蒸汽与冷力；GHG Protocol Scope 2 Guidance 明确四类能源载体（electricity, steam, heat, cooling）。
- 建议：统一为「外购电力、蒸汽、热力、冷力」，并在深度解析补一句"自发电自用计 Scope 1，不外购部分不计 Scope 2"。

### L54655 | 第三十一章2题 | 无绿证时市场基是否等于地点基
- 类型：1 事实错误
- 严重度：P2
- 原文：「是，此时无专属契约，市场基只能采用电网平均合约因子，数值与地点基趋同」
- 问题：市场基在无合约时应使用 **residual mix（残余电网组合）因子**，即从电网平均中扣除已被声明/注销的绿电，通常**高于**地点基（绿电占比越高的电网差异越大）。说"等于/趋同"会掩盖两法差异的来源。
- 建议：改为「用 residual mix 因子，一般略高于地点基；只有在该区域无 residual mix 数据、退回电网平均因子时才近似相等，且须披露该假设」。

### L54757 | 第三十一章7题 | LCIA 是否加权
- 类型：1 事实错误
- 严重度：P2
- 原文：「LCIA 把 CO₂/CH₄ 归为'气候变化'等类别，再加权得单一分数」
- 问题：ISO 14044 中 **weighting（加权）是可选项**，且规定"用于对外公开的比较论断时不得使用加权单一分数"；碳足迹场景通常只到**中点指标（kgCO₂e）**就停，不做端点/加权。写成流程必经步骤会误导。
- 建议：改为「LCIA 先分类（classification）再特征化（characterization）得 kgCO₂e 等中点结果；归一化与加权为可选步骤，且对外比较论断中禁用」。

### L54779 | 第三十一章8题 | 初级数据的判定
- 类型：1 事实错误（存疑）
- 严重度：P2
- 原文：「把'供应商提供的平均值'误当初级数据——须经审计确认」
- 问题：ISO 14067/GHG Protocol 对初级数据的定义是"来自该特定供应商/特定过程的数据"，**供应商提供的其自身平均值就是初级数据**（区别于行业平均的次级数据）；是否经第三方核查是"数据质量/可信度"问题，不是"是否初级"的判定标准。此说法会让读者把数据层级与核查状态混为一谈。
- 建议：改为「供应商针对本企业供货批次实测或按其自身产线核算并提供的数据属初级；行业数据库平均值属次级。供应商数据未经核查只是降低其 DQR/可靠性评分，不改变层级；若供应商给的是行业平均值，则仍属次级」。

### L54719 | 第三十一章5题 | 区域电网因子更新口径
- 类型：1 事实错误
- 严重度：P2
- 原文：「生态环境部逐年发布各区域电网基准线排放因子，分电量边际与容量边际」
- 问题：①"逐年发布"不准确，电力平均因子 2024 年才首次成体系发布（2021、2022 年度），此前是分年度零散发布；②"分电量边际与容量边际"是**基准线**因子口径（见 L54646），与企业核算用的平均因子不是一套；③"每季度同步官方公告"夸大更新频率。
- 建议：改为「生态环境部/国家统计局按年度发布全国及区域电力平均二氧化碳排放因子（2024 年首次发布 2021、2022 年度值）；基准线 OM/BM 因子另属 CDM/CCER 体系。系统按年度版本化，并区分『核算因子』与『基准线因子』两个因子域」。

### L54834 | 第三十一章11题 | "确定性边界"这个术语
- 类型：1 事实错误
- 严重度：P1
- 原文：「确定性边界（组织边界）指被纳入核算的实体/设施范围」
- 问题：标准里没有"确定性边界"这个概念，ISO 14064-1 / GHG Protocol 的对应术语是 **organizational boundary（组织边界）**，与 operational boundary（运行边界，即 Scope 1/2/3 的排放类别划分）配对使用。"确定性边界"是生造词，且题干把它与"系统边界"并列，会让人误以为 ISO 有"确定/不确定"两类边界。另外"从摇篮到 grave/gate"中英混排也不规范。
- 建议：改为「组织边界（organizational boundary，用运营控制/财务控制/股权比例法确定纳入哪些实体）与运行边界（operational boundary，确定纳入哪些排放类别）；产品侧另有系统边界（cradle-to-gate / cradle-to-grave）」。

### L54937 | 第三十一章16题 | avoided burden 与双重计算
- 类型：1 事实错误
- 严重度：P1
- 原文：「归因采用'避免双重计算'的让步法（avoided burden）」
- 问题：两处错。①**avoided burden（避免负担/替代法）**是回收料、副产品、替代能源场景下"把避免的排放记给某一方"的**分配/建模方法**，与"避免双重计算"是完全不同的概念（后者是边界去重原则）；②Scope 3 的归因主方法是**分配（allocation）**：物理量（质量/体积/热值）或经济价值分摊，加上"归属原则"（谁的 Scope 1 就是谁的 Scope 3）。把 avoided burden 当 Scope 3 归因方法属于概念错配，懂行的面试官会直接判定"没做过核算"。
- 建议：改为「共同生产过程按物理量或经济价值分配（ISO 14044 层级：先细分、再物理、后经济）；跨企业边界去重靠归属原则（供应商 Scope 1 ↔ 本企业 Scope 3.1）；avoided burden 仅用于回收/替代情景，且 GHG Protocol 产品标准要求单独披露、不得与自身排放直接相减」。

### L55034 | 第三十二章2题 | GRI 行业标准数量
- 类型：3 数字错误
- 严重度：P0
- 原文：「截至 2023 年 GRI 已发布 40 个行业标准覆盖多数高影响行业」
- 问题：**40 是 GRI 行业计划的规划总数，不是已发布数**。GRI 官方（Sector Program 页面）明确"seeking to develop standards for 40 sectors"，实际已发布仅 **4 个：GRI 11 石油天然气（2021）、GRI 12 煤炭（2022）、GRI 13 农林渔（2022）、GRI 14 采矿（2024）**；纺织服装、金融服务仍在制定中。把它写成"已发布 40 个覆盖多数行业"，是最容易被追问打穿的硬数字错误。
- 建议：改为「GRI 计划覆盖约 40 个行业，目前实际发布 4 个（GRI 11/12/13/14），纺织服装、食品饮料、金融服务在制定中；未覆盖行业仅用 GRI 1/2/3 并作说明」。

### L55089 | 第三十二章5题 | IFRS S2 的 Scope 3 与豁免
- 类型：1 事实错误 / 4 过时
- 严重度：P1
- 原文：「Scope 3 在方法不可得时可暂不披露但须说明…未上市公司或方法缺失可豁免并解释（"safe harbour"过渡）」
- 问题：①S2 **不区分上市/非上市**，豁免来自各司法管辖区的采纳范围，标准本身没有"未上市公司可豁免"；②Scope 3 是强制披露项（允许用估算、行业平均值、代理数据），仅有的过渡救济是"适用首年可不披露 Scope 3 "及部分 Cat 15 救济，不存在"方法不可得即可不披露"的通用豁免；③"safe harbour"是部分司法辖区（如美国加州/SEC 旧提案）的诉讼免责概念，不是 ISSB 术语，张冠李戴；④**过时**：ISSB 已于 **2025-12-11 发布《Amendments to Greenhouse Gas Emissions Disclosures》**（2027-01-01 起适用，可提前），明确 Cat 15 可只报 financed emissions、允许排除衍生品/便利型融资/保险关联排放、GWP 允许按辖区要求用非最新 AR 值。文中完全未反映。
- 建议：改写为「S2 要求 Scope 1/2/3 全披露，Scope 3 允许估算并说明方法与数据限制；救济仅限：适用首年免披 Scope 3、Cat 15 仅报 financed emissions、辖区强制不同方法/GWP 时的辖区豁免（2025-12 修订，2027 生效）。无『未上市公司豁免』一说」。

### L55383 | 第三十二章19题 | S2 是否强制 Scope 3
- 类型：5 逻辑矛盾
- 严重度：P1
- 原文：「GHG Protocol 要求 Scope 1/2 必报，Scope 3 建议。IFRS S2 强制 Scope 1/2/3。」
- 问题：与 5 题（L55089）「Scope 3 方法不可得可暂不披露」直接冲突；同一份题库里两题结论相反，且 19 题这句更接近标准原文（S2 确实强制三类范围，Scope 3 不能因"不重要"而免披），5 题的表述才是错的。另"GHG Protocol 要求 Scope 1/2 必报、Scope 3 建议"也不准：Scope 3 按"重要性/相关性"筛别，若已识别为相关且重大则必须报，不是一律建议。
- 建议：以 19 题口径为准，反向修正 5 题；并给出一句统一口径「S2：Scope 1/2/3 均强制，Scope 3 允许估算+首年过渡；GHG Protocol：Scope 3 按重大性筛别，排除须说明理由」。

### L55142 | 第三十二章7题 | ESRS 与 ISSB 互操作指南时间
- 类型：3 日期错误 / 4 过时
- 严重度：P1

### L55023 | 第三十二章1题 | GRI 3 的四步
- 类型：1 事实错误
- 严重度：P2
- 原文：「④ 确定实质性议题并获治理层确认，最终在 GRI 3-3 中列示」
- 问题：GRI 3 四步的第四步是 **"Prioritise the most significant impacts for reporting"（对最重大影响排序并确定报告议题）**，"获治理层确认"是 GRI 1/2 的报告治理要求（GRI 2-14），不在四步之内；四步里也没有"实质性议题"这一说法（2021 版已改称 material topics = 最重大影响）。
- 建议：第四步改为「按影响严重程度排序，确定 material topics（报告议题）」，治理层审批另作一句说明。

### L55364 | 第三十二章18题 | IFRS 接管对象表述
- 类型：1 事实错误
- 严重度：P2
- 原文：「2022 年 IFRS 基金会完成对 SASB 标准制定方（VASB/SASB）与 CDSB 的接管…CDSB 框架用于自然相关披露基础」
- 问题：①不存在 "VASB" 这个机构，SASB 的标准制定主体是 **SASB Standards Board**，其上级是 **价值报告基金会 VRF**（2021 年由 SASB 基金会与 IIRC 合并而成），2022 年 VRF 并入 IFRS 基金会；②CDSB 于 2022-01 并入 IFRS 基金会，其**气候/自然资本**披露指引仅作为参考材料，ISSB 的"自然相关"议题由 **TNFD** 承接并在 2025-2026 立项，说"CDSB 框架用于自然相关披露基础"（7 题 L55132 同）不准确。
- 建议：改为「2022 年 IFRS 基金会合并价值报告基金会（含 SASB Standards Board）与 CDSB；SASB 指标成为 S1/S2 的行业指标来源，CDSB 的水/生物多样性指引作为参考，自然相关议题由 TNFD 与 ISSB 自然项目承接」。

## 第三十三章 碳中和政策与碳市场（Q1-Q20）

### L55507 | 第三十三章5题 | EU ETS 覆盖范围
- 类型：4 过时 / 1 事实错误
- 严重度：P1
- 原文：「① 覆盖行业更广且已扩至交通建筑（试点）」
- 问题：EU ETS **尚未**覆盖建筑与道路交通。EU ETS2（separate emissions trading system for buildings, road transport and small industry）由 Directive (EU) 2023/959 设立，**2027 年才启动**（若 2024–2026 年能源价格异常，欧委可延至 2028）。写成"已扩至…（试点）"是把已立法未实施当成已运行；另外已实际扩围的是**海运（2024 年起）**，文中未提，却是最该说的例子。
- 建议：改为「① 覆盖范围持续扩张：2024 年起纳入海运（逐步 100% 履约），2027 年起另设 EU ETS2 覆盖建筑与道路交通燃料（可与 2028 年延期）；与 CEA 相比行业更广、拍卖比例更高」。

### L55478 | 第三十三章3题 | CEA 价格形成
- 类型：1 事实错误
- 严重度：P2
- 原文：「由二级市场供需决定，开盘价由政策设定区间，后续由买卖撮合」
- 问题：全国碳市场挂牌协议交易没有"政策设定开盘价区间"这一机制，实际是**申报撮合 + 涨跌幅限制（挂牌协议 ±10%）**、大宗协议另设区间；"政策设定"的是配额总量与分配，不是开盘价。
- 建议：改为「价格由挂牌协议/大宗协议撮合形成，交易所设涨跌幅限制与最小价格变动单位；政府通过配额总量、分配方案与有偿分配比例间接影响价格，不直接定价」。

### L55489 | 第三十三章4题 | CCER 项目类型
- 类型：5 逻辑矛盾
- 严重度：P2
- 原文：「项目类型聚焦林业、光热、海风、甲烷等」
- 问题：首批（2023-10 发布、2024-01 市场启动）方法学只有 4 个：造林碳汇、红树林营造、并网光热发电、并网海上风电，**没有甲烷类**；13 题（L55674）也准确写成"造林碳汇、红树林营造、光热发电、海上风电"。同一章两题口径不一致，且"甲烷"当时仅是后续征集的候选方向。
- 建议：4 题改为与 13 题一致的四个首批方法学，并补一句「煤矿低浓度瓦斯/隧道照明等第二批方法学正在推进，以生态环境部公告为准」。

### L55529 | 第三十三章6题 | CBAM 覆盖品类与氢
- 类型：1 事实错误
- 严重度：P2
- 原文：「覆盖六大类：钢铁、铝、水泥、化肥、电力，以及 2023 年起扩展纳入的氢」
- 问题：氢自 Regulation (EU) 2023/956 **立法之初就在 Annex I 内**，不存在"2023 年起扩展纳入"；"六大类"本身对（水泥、电力、化肥、钢铁、铝、氢）。另外未提 2025 年 CBAM 简化（拟对年累计净重 <50 吨的进口人免报，覆盖约 90% 进口商，具体以已生效实施条例为准，**存疑待核**），面试若被追问"小批量出口还要报吗"会答不上。
- 建议：改为「覆盖水泥、电力、化肥、钢铁、铝、氢六类（氢自始纳入）；另以实施条例设最小免报阈值（<50 t/年），并注意 CN 码范围以 Annex I 最新版为准」。

### L55550 | 第三十三章7题 | CBAM 证书计价与清缴
- 类型：3 数字错误
- 严重度：P2
- 原文：「碳价差 = 当周 EU ETS 平均拍售价…2026 起进口商按缺口购证清缴」
- 问题：①CBAM 证书价格取**上一日历周 EU ETS 拍卖收盘均价**（Commission 实施条例口径），不是"当周"；②清缴不是当年完成：2026 年进口的货物，进口商在 **2027 年起每年 5 月 31 日前**清缴上一年度证书，且 2026 年起免费配额退坡系数（CBAM factor）逐年上升，公式里应写"×(1−免费配额退坡系数)"而不是笼统的"抵扣比例"。
- 建议：改为「证书价 = 前一周 EU ETS 拍卖均价；应清缴量 = 嵌入排放 × CBAM factor（2026 起 2.5%→2034 年 100%）；每年 5 月 31 日前清缴上一年度，已在他国实付碳价可凭证据扣减」。

### L55579 | 第三十三章8题 | 全国因子与省级因子的偏差方向
- 类型：1 事实错误（存疑）
- 严重度：P2
- 原文：「全国因子偏保守、易高估排放，适合无细分数据时粗算」
- 问题：偏差方向不能一概而论：全国平均因子低于煤电占比高的区域（如华北），高于水电占比高的区域（如华中、西南），所以对前者是低估、后者才是高估。说"全国因子偏保守、易高估"在多数高耗能省份恰好相反；且现行发电行业核算指南**统一要求用全国电力平均因子**，"合规核算优先省级"对纳管企业并不成立。
- 建议：改为「纳管企业按行业核算指南指定口径（发电行业用全国电力平均因子）；自愿核算/PCF 可用省级或区域因子以体现区位差异，须在报告中声明所选层级；全国 vs 省级的偏差方向取决于当地电源结构，不能笼统说高估」。

### L54524 | 第三十章13题 | CSRF 覆盖缺失
- 类型：6 内容问题
- 严重度：P2
- 原文：「或在 STATLESS 下仍启用 CsrfFilter 与表单登录」
- 问题：全章 17 题没有 CSRF 专题（CSRF 与 CORS 是本节要求核对的重点），只用这一句"易错点"带过，且隐含"无状态就关掉 CSRF"的结论——若 token 存 Cookie（本章 Q10 追问 1 正是把 refresh token 放 HttpOnly Cookie），仍必须做 CSRF 防护（double submit / SameSite=Lax / 自定义头校验）。另 `STATLESS` 拼写错误（应为 `STATELESS`），照抄进代码会编译失败。
- 建议：补一题「JWT 放 Header 与放 Cookie 的 CSRF 风险差异」；易错点改为「无状态 API 用 Authorization 头时 CSRF 风险低可关闭 CsrfFilter；一旦用 Cookie 承载凭证（如 refresh token）必须保留 CSRF 防护并与 CORS 白名单配合，禁止 `allowCredentials(true)` + `allowedOrigins("*")` 组合」。
